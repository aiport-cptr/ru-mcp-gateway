# Изменения

## 0.4.1 — группы, Диадок, СБИС, Яндекс 360

Дизайн: [docs/design/0.4.1-integrations.md](docs/design/0.4.1-integrations.md).

- **Группы**: `rugw groups add|remove|list`, права на `group:<имя>`.
- **Диадок** (только чтение): вход администратора `rugw diadoc login` (OIDC Device Flow),
  refresh-токен зашифрован, ротация с CAS; ящики и документы; `autoRegister=false`.
- **СБИС** (только чтение): документы по типу; повторный вход при 401; ссылки на вложения не отдаются.
- **Яндекс 360 от имени сотрудника** (только чтение): Диск (список, последние, текстовые файлы до 1 МБ),
  Почта (поиск и чтение по IMAP только на чтение, без пометки прочитанным).
- `rugw credentials rotate` перешифровывает и служебные токены.
- Исправлено: проверка прав Яндекса в настройках не пропускала точку (`cloud_api:disk.read`).
- Миграция `0007`.

## 0.4.0 — диагностика и новые коннекторы

Дизайн: [docs/design/0.4-connectors.md](docs/design/0.4-connectors.md).

- **Коды ошибок и номер запроса**: каждая ошибка инструмента содержит стабильный код
  (`ACCESS_DENIED`, `UPSTREAM_AUTH`, `RELOGIN_REQUIRED`, …) и номер `rq-…`; номер пишется в аудит
  (миграция `0006`) и лог; `rugw audit list --request rq-…`. Неожиданные ошибки — `INTERNAL`
  без текста исключения.
- **Коннекторы**: amoCRM (сделки с правами по воронке, контакты, примечания), МойСклад
  (справочники, документы, остатки), Контур.Фокус (сведения по ИНН/ОГРН), Wildberries
  (остатки, заказы, продажи), Ozon (товары, остатки, отправления FBS). Новые — только чтение,
  кроме примечаний amoCRM.
- **Трекер**: в карточке задачи скрыты связанные задачи из недоступных очередей.
- **Логи**: отключён лог `httpx` с полными адресами запросов (в них бывали секреты).
- Шлюз не стартует, если коннектор не объявлен в списке, на который выдаются права.

## 0.3.1 — исправления по проверке 0.3

Подробно: [docs/reviews/2026-10-06-codex-v03.md](docs/reviews/2026-10-06-codex-v03.md).

- Обновление токена Яндекса больше не восстанавливает доступ заблокированного сотрудника и не
  затирает токены нового входа: условная запись по поколению (CAS), миграция `0005`.
- Сохранение токенов при входе согласовано с `users disable` блокировкой строки пользователя.
- Корректность не зависит от числа процессов шлюза.
- Тесты проверяющего перенесены в репозиторий.

## 0.3.0 — права на ресурсы и Трекер от имени сотрудника

Дизайн: [docs/design/0.3-access.md](docs/design/0.3-access.md).

- **Права на ресурсы** (`resource_grants`): кому (роль или конкретный email) → коннектор → ресурс
  (очередь Трекера, воронка сделок Битрикс24, набор 1С; шаблоны с `*`) → чтение/запись.
  Итог = min(потолок роли, max по правам). Админ — всё. Изменения действуют сразу.
- Проверка до запроса по аргументам и после — по фактическим данным: перемещённая задача Трекера
  проверяется по её настоящей очереди, сделка — по воронке из ответа портала; поиск и списки
  фильтруются. Навигация OData через «/» без доступа ко всем наборам 1С запрещена.
- Список инструментов показывает только коннекторы, к которым есть доступ; отказы по ресурсу
  пишутся в аудит как `denied`. `gateway_whoami` показывает доступные ресурсы.
- **Трекер от имени сотрудника** (`RUGW_TRACKER_AUTH_MODE=user`): токен Яндекса сотрудника
  хранится зашифрованным (Fernet, ротация ключей), обновляется автоматически, удаляется
  при блокировке пользователя.
- Консоль: `rugw grants list|add|remove`, `rugw credentials rotate`.
- Ошибки конфигурации печатаются без введённых значений (раньше pydantic мог показать часть секретов).
- Миграция `0004`: права по умолчанию повторяют поведение 0.2.

## 0.2.1 — исправления по независимой проверке

Подробно: [docs/reviews/2026-10-06-codex.md](docs/reviews/2026-10-06-codex.md).

- **Безопасность (P1):** повторный вход больше не возвращает роль `admin` после понижения.
- **Безопасность (P1):** параллельный повтор refresh-токена отзывает весь грант; повтор кода
  авторизации отзывает выданные по нему токены. Миграция `0003` (`grants.auth_code_hash`).
- **Надёжность (P2):** ошибки OAuth больше не подменяются `FrozenInstanceError` (500 вместо 400).
- **Безопасность (P2):** тексты ошибок внешних систем не передаются модели и в аудит —
  только статус, код и id запроса.

## 0.2.0

- **Миграции схемы базы (Alembic).** `serve` применяет их при старте; команда `rugw migrate [--status]`.
  База от 0.1 подхватывается без потери данных.
- **Ограничение частоты запросов**: `/register` и вход — по IP, `/mcp` — по токену и по IP.
  Ответ `429` с `Retry-After`. `X-Forwarded-For` учитывается только от доверенных прокси.
- **Очистка**: раз в час удаляются истёкшие незавершённые входы, коды, токены, пустые гранты
  и аудит старше `RUGW_AUDIT_RETENTION_DAYS`. Использованные refresh-токены хранятся до срока,
  чтобы распознавать повторное использование. Команда `rugw cleanup`.
- **Аудит из консоли**: `rugw audit list` с фильтрами, `rugw audit export` в JSONL или CSV.
- Тесты гоняются и на SQLite, и на PostgreSQL (в CI — оба).
