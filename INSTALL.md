# Установка ru-mcp-gateway

Около 30 минут. Ставите сами — по этой инструкции. Ставит ИИ-помощник — дайте ему
[INSTALL_FOR_AI.md](INSTALL_FOR_AI.md).

## Что понадобится

- **Сервер** на Ubuntu 22.04 или 24.04: от 1 ГБ свободной памяти и 3 ГБ диска.
  Подойдёт и сервер, где уже работают другие сайты и контейнеры: шлюз от них изолирован
  (свои контейнеры, база и том; порт только на 127.0.0.1; потолок памяти и процессора).
- **Поддомен**, например `mcp.company.ru`, с A-записью на IP сервера.
- **OAuth-приложение Яндекса** — через него сотрудники входят в шлюз (шаг 3).
- Доступ к серверу по SSH с правами sudo.

## 1. Docker и код

```bash
sudo apt-get update && sudo apt-get install -y git docker.io docker-compose-v2
sudo git clone https://github.com/aiport-cptr/ru-mcp-gateway.git /opt/rugw
cd /opt/rugw
```

Docker уже стоит — первую команду пропустите (нужен Compose v2: `docker compose version`).

## 2. Установщик

```bash
sudo deploy/install.sh --domain mcp.company.ru --admin you@company.ru --allowed-domains company.ru
```

- `--admin` — кто станет администратором при первом входе;
- `--allowed-domains` — почтовые домены сотрудников, которых пускать (или `--allowed-emails` — отдельные адреса).

Установщик:
- создаёт `.env` (права 600), **сам генерирует** пароль базы и ключ шифрования — придумывать их не нужно;
- выбирает свободный локальный порт шлюза (8000, 8001, …);
- смотрит, кто занимает порты 80 и 443, и выбирает способ HTTPS:

| Что на сервере | Способ | Что сделает установщик |
|---|---|---|
| порты 80 и 443 свободны | `caddy` | запустит встроенный Caddy: сертификат Let's Encrypt получится сам |
| nginx | `nginx` | подготовит файл сайта `deploy/generated/rugw-<домен>.conf`; nginx не трогает |
| Caddy | `caddy-host` | подготовит блок `deploy/generated/Caddyfile-<домен>` |
| другое | `external` | подскажет, куда направить поддомен в вашем прокси |

Способ можно задать явно: `--proxy nginx`.

Установщик не печатает секреты, не трогает чужие контейнеры и настройки других сайтов,
не открывает порты в файрволе. Запускать повторно безопасно — заполненное он не меняет.

При первом запуске он остановится и попросит OAuth-приложение Яндекса — это шаг 3.

## 3. OAuth-приложение Яндекса

1. https://oauth.yandex.ru/client/new → «Веб-сервисы».
2. Права: «Доступ к адресу электронной почты», «Доступ к логину, имени и фамилии».
   Для доступа от имени сотрудника (Трекер, Диск, Почта) — ещё права из раздела настроек ниже.
3. Redirect URI — его печатает установщик: `https://<домен>/auth/yandex/callback`.
4. Впишите ClientID и Client secret в `.env` на сервере:

```bash
sudo nano /opt/rugw/.env      # RUGW_YANDEX_CLIENT_ID=…  RUGW_YANDEX_CLIENT_SECRET=…
```

Если запускаете установщик сами в терминале, он спросит их (ввод секрета скрыт).
**Секреты не отправляйте в чаты, почту и мессенджеры, в том числе ИИ-помощнику.**

Запустите установщик ещё раз — он проверит настройки и запустит шлюз:

```bash
sudo deploy/install.sh
```

## 4. HTTPS через прокси сервера

Пропустите, если установщик выбрал `caddy`.

**nginx.** Инструкция — в начале подготовленного файла. Коротко:

```bash
sudo certbot certonly --nginx -d mcp.company.ru
sudo cp deploy/generated/rugw-mcp.company.ru.conf /etc/nginx/sites-available/
sudo ln -s /etc/nginx/sites-available/rugw-mcp.company.ru.conf /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

`nginx -t` проверяет конфигурацию до применения: если он ругается — не перезагружайте nginx,
работающие сайты не пострадают.

**Caddy.**

```bash
sudo deploy/apply-caddy.sh
```

Скрипт делает копию `/etc/caddy/Caddyfile`, дописывает блок шлюза, проверяет настройки
(`caddy validate`) и только тогда мягко перезагружает Caddy — другие сайты не прерываются.
Если проверка не прошла, файл возвращается как был.

**Другой прокси** (Traefik, nginx в контейнере, панель хостинга): направьте `https://<домен>`
на `http://127.0.0.1:<порт>` (порт — `GATEWAY_HOST_PORT` в `.env`). Требования: передавать
заголовок Host, не буферизовать ответы, таймаут чтения от 1 часа.

## 5. Проверка

```bash
sudo deploy/check.sh
```

Проверяет контейнеры, что порт шлюза закрыт снаружи, настройки, базу, HTTPS, OAuth-метаданные
и что `/mcp` без входа отвечает 401. Все пункты с ✓ — готово.

## 6. Подключение

Claude Code:

```bash
claude mcp add --transport http company https://mcp.company.ru/mcp
```

Другие клиенты с поддержкой удалённых MCP-серверов (в том числе Claude в браузере и в приложении) —
добавьте свой коннектор с тем же адресом. Клиент откроет браузер: вход через Яндекс → «Разрешить» → готово. Первым входите вы —
адрес из `--admin` получит роль администратора.

## Коннекторы

Включаются, когда в `.env` заданы их учётные данные (подсказки — прямо в `.env`). После правки:

```bash
sudo docker compose up -d && sudo deploy/check.sh
```

`check.sh` покажет, какие коннекторы включились. Права сотрудников — в [README](README.md#права-на-ресурсы).

## Обновление

```bash
cd /opt/rugw && sudo deploy/update.sh
```

Делает резервную копию базы, берёт новую версию, пересобирает и проверяет.
Миграции базы применяются сами. Что изменилось — [CHANGELOG.md](CHANGELOG.md).

## Резервные копии

```bash
sudo deploy/backup.sh                    # копия базы в backups/, хранятся последние 14
```

Ежедневно по cron (`sudo crontab -e`):

```
15 3 * * * cd /opt/rugw && deploy/backup.sh >/dev/null
```

**Отдельно сохраните `.env`** (в надёжное место, не в чат): в нём ключ шифрования. Без него
сохранённые токены сотрудников и Диадока не прочитать — придётся входить заново.

Восстановление:

```bash
sudo docker compose stop gateway
sudo docker compose exec -T postgres pg_restore -U rugw -d rugw --clean --if-exists < backups/<файл>.dump
sudo docker compose start gateway
```

## Удаление

```bash
cd /opt/rugw && sudo docker compose down        # остановить; база сохраняется
```

`docker compose down -v` удаляет базу безвозвратно — только если она точно не нужна
и копия сделана.

## Если что-то не так

| Симптом | Что проверить |
|---|---|
| установщик: «Осталось заполнить в .env» | шаг 3 |
| установщик: ошибки настроек с именами полей | исправьте поля в `.env`; значения в выводе не показываются намеренно |
| check: HTTPS не открывается | A-запись (`getent hosts <домен>`), порты 80/443 в файрволе облака, шаг 4 |
| check: OAuth-метаданные issuer не совпадает | `RUGW_PUBLIC_URL` в `.env` должен быть `https://<домен>` без пути |
| вход Яндекса: redirect_uri mismatch | Redirect URI в приложении Яндекса совпадает с адресом из установщика |
| шлюз перезапускается | `sudo docker compose logs --tail 50 gateway` |

Ошибки инструментов содержат код и номер запроса — см. [README](README.md#если-что-то-не-работает).
