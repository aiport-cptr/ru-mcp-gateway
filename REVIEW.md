# Инструкция для проверяющей системы

Этот репозиторий пишется ИИ-ассистентом (Claude). Независимая проверка — обязательная
часть процесса. Ниже — что проверять в первую очередь и как сообщать о находках.

## Как запустить

```bash
uv sync
uv run pytest -q          # все тесты должны пройти
uv run ruff check src tests
```

## Приоритет проверки

1. **`src/rugw/auth/`** — вход, согласие, выдача и ротация токенов. Ошибка здесь = доступ постороннего.
   - Может ли код/токен быть использован повторно, другим клиентом, после отзыва, после блокировки пользователя?
   - Можно ли получить код без экрана согласия или подделать форму согласия?
   - Корректна ли проверка домена почты (`policy.admission_role`)?
   - Правильно ли привязан `resource` (RFC 8707) и проверяется ли он на `/mcp`?
2. **`src/rugw/tools.py`** — проверка роли и аудит вокруг каждого инструмента.
   Есть ли путь вызвать инструмент в обход `guarded` или увидеть недоступный в `tools/list`?
3. **`src/rugw/config.py`** — может ли шлюз стартовать в небезопасной конфигурации?
4. **`src/rugw/connectors/`** — инъекции в URL/путь внешней системы, утечка секретов в ошибках,
   неограниченный объём ответа, возможность записи у read-инструментов.
5. **Развёртывание** — `Dockerfile`, `docker-compose.yml`, `deploy/Caddyfile`: порт только на 127.0.0.1,
   непривилегированный пользователь, нет секретов в образе.

Модель угроз и известные ограничения — [SECURITY.md](SECURITY.md). Ограничения из списка
«известные» не нужно сообщать как новые находки, если только оценка их риска не занижена.

## Формат находки

Откройте issue (для уязвимостей — без деталей эксплуатации, см. SECURITY.md) с полями:

```
Серьёзность: критично | высоко | средне | низко | замечание
Файл и строки:
Что не так:
Как воспроизвести (или тест, который должен падать):
Предлагаемое исправление:
```

Лучшая форма находки — **падающий тест** в `tests/`. Его добавят в набор, и исправление будет считаться
завершённым, только когда тест проходит.

## Чего не делать

- Не запускать против реальных систем компании и не просить реальные учётные данные.
- Не коммитить секреты, даже тестовые, похожие на настоящие.
