# Безопасность

## Что защищаем

1. Данные во внешних системах (Трекер, CRM, 1С) от чтения и изменения посторонними.
2. Учётные данные коннекторов (токены, вебхуки, пароли 1С).
3. Токены доступа сотрудников к шлюзу.

## Кому не доверяем

| Кто | Что может | Чем закрыто |
|---|---|---|
| Аноним из интернета | Слать запросы на `/mcp`, `/register`, `/authorize` | `/mcp` без валидного токена → 401. Регистрация клиента не даёт доступа без входа сотрудника |
| Злоумышленник, зарегистрировавший клиента со своим redirect_uri | Прислать сотруднику ссылку на `/authorize` | Обязательный экран согласия с именем клиента и хостом возврата; без нажатия «Разрешить» код не выдаётся |
| Сотрудник с ролью `readonly` | Вызывать любые инструменты по имени | Роль проверяется на каждом вызове; write-инструменты не видны и не вызываются |
| Уволенный сотрудник | Пользоваться ранее выданным токеном | `users disable` отзывает все гранты; проверка `disabled` на каждом запросе |
| Укравший refresh-токен | Получать новые access-токены | Ротация refresh; повтор уже использованного → отзыв всей цепочки |
| Укравший базу данных | Использовать токены из базы | В базе только SHA-256 хеши токенов и кодов |
| Поток запросов (перебор, засорение `/register`) | Регистрировать клиентов массово, перебирать токены | Ограничение частоты: `/register` и вход — по IP, `/mcp` — по токену и по IP (×5) |
| Сайт в браузере сотрудника | DNS rebinding к шлюзу, CSRF на экран согласия, clickjacking | Проверка `Host`/`Origin` на `/mcp`; CSRF-cookie `SameSite=Strict` + одноразовый токен формы; `X-Frame-Options: DENY` |
| Модель (prompt injection из данных) | Попросить инструмент сделать лишнее | Инструменты делают только перечисленное; коннекторы валидируют ввод (ключи задач, имена наборов 1С, белый список сущностей CRM); 1С — только чтение |

## Решения

- **Нет режима без авторизации.** Конфиг падает при http без dev_mode, dev_mode вне localhost,
  SQLite в проде, заглушках вместо секретов, пустом списке допуска, `default_role=admin`.
- **Протокол OAuth** (DCR, PKCE, обмен кода, отзыв, метаданные) реализует официальный MCP SDK,
  а не собственный код.
- **Токены — непрозрачные случайные строки** (256 бит), не JWT: отзыв действует сразу.
- **Права — по роли из базы**, а не по scope в токене: понижение роли действует сразу.
- **Токен Яндекса** используется один раз для получения профиля и не сохраняется. К Яндексу
  тоже применяется PKCE.
- **Аудит** пишет аргументы вызова с маскировкой ключей, похожих на секреты, и обрезкой длины.
  Учтите: в аудит попадают поисковые запросы и тексты комментариев — это персональные данные.
- **Ошибки внешних систем**: модели и в аудит уходят только система, HTTP-статус, короткий код
  ошибки и id запроса (проверяются по шаблону). Тело ответа — только в лог сервера на уровне DEBUG.
  Неожиданные исключения SDK скрывает от клиента.
- **Повтор одноразовых значений** (код авторизации, refresh-токен), в том числе параллельный,
  отзывает соответствующий грант. Роль из `bootstrap_admin_emails` назначается только при первом входе.

## Известные ограничения MVP

- Коннекторы работают от **сервисной учётной записи**: все пользователи с доступом к инструменту
  действуют с её правами. Выдавайте сервисным учёткам минимальные права.
- Ограничение частоты хранится в памяти процесса: при нескольких репликах шлюза лимит действует
  на каждую отдельно. Поддерживается один экземпляр.
- `X-Forwarded-For` учитывается только от доверенных прокси (`RUGW_TRUSTED_PROXY_CIDRS`, по умолчанию
  localhost и сети Docker `172.16.0.0/12`). Другой контейнер в той же сети Docker может подставить
  чужой IP и обойти лимит по IP — не размещайте рядом с шлюзом недоверенные контейнеры или сузьте список.
- `/register` открыт (так требует MCP-клиентам DCR); он ограничен по частоте, но записи
  о клиентах не удаляются автоматически.
- В журнале аудита — поисковые запросы и тексты комментариев (персональные данные); срок хранения
  задаётся `RUGW_AUDIT_RETENTION_DAYS` (по умолчанию 365 дней).
- Отзыв токена публичным клиентом через `/revoke` требует пустого `client_secret` (особенность SDK).
- Не проводился внешний пентест.
