# Устройство

```
MCP-клиент ──HTTPS──▶ Caddy ──127.0.0.1:8000──▶ rugw (Starlette + MCP SDK) ──▶ Трекер / Битрикс24 / 1С
                                                     │
                                                     └──▶ PostgreSQL (пользователи, токены, аудит)
```

## Модули

| Файл | Назначение |
|---|---|
| `config.py` | Настройки из `RUGW_*`, проверки fail-closed |
| `db.py` | Модели SQLAlchemy |
| `security.py` | Генерация и хеширование секретов, маскировка для аудита |
| `auth/yandex.py` | Обмен кода Яндекса на профиль (PKCE) |
| `auth/provider.py` | Хранилище OAuth для MCP SDK: клиенты, коды, гранты, токены |
| `auth/routes.py` | Возврат из Яндекса и экран согласия |
| `policy.py` | Допуск по почте, роли и уровни инструментов |
| `tools.py` | `GatewayServer` (фильтр `tools/list`) и обёртка `guarded` (права + аудит) |
| `connectors/` | Коннекторы; каждый возвращает список `ToolSpec` |
| `ratelimit.py` | Ограничение частоты запросов (ASGI middleware, token bucket) |
| `maintenance.py` | Очистка истёкших записей и старого аудита |
| `migrate.py`, `migrations/` | Миграции схемы базы (Alembic) |
| `app.py` | Сборка приложения; при старте проверяет версию схемы и запускает фоновую очистку |
| `__main__.py` | `serve`, `migrate`, `cleanup`, `users`, `audit` |

## Поток входа

1. Клиент регистрируется (`/register`, DCR) и открывает `/authorize` с PKCE.
2. `provider.authorize` сохраняет запрос (`pending_logins`, по хешу state) и уводит браузер в Яндекс (тоже с PKCE).
3. `/auth/yandex/callback`: код Яндекса → профиль → допуск по почте → пользователь в базе →
   экран согласия (CSRF-cookie + одноразовый токен формы).
4. `/auth/consent` «Разрешить»: запрос атомарно помечается использованным, выдаётся одноразовый
   код (5 минут), браузер возвращается на redirect_uri клиента.
5. `/token` (SDK проверяет PKCE и redirect_uri) → `exchange_authorization_code` создаёт грант
   и пару access (1 час) + refresh (30 дней).
6. `/mcp` с `Bearer`: SDK вызывает `load_access_token`, проверяет `resource`; каждый вызов
   инструмента проходит `guarded`.

## Добавить коннектор

1. `src/rugw/connectors/<имя>.py` с функцией `build(settings, http) -> list[ToolSpec]`;
   возвращать `[]`, если не заданы учётные данные.
2. Для каждого инструмента — честный уровень: `READ`, если ничего не меняет; иначе `WRITE`.
3. Валидировать всё, что попадает в путь URL; ограничивать объём ответа (`clip`).
4. Ошибки внешней системы — через `ConnectorError` без секретов в тексте.
5. Добавить в `BUILDERS`, настройки — в `config.py` и `.env.example`, тесты — в `tests/test_connectors.py`.

## Схема базы

Изменения схемы — только через миграции в `src/rugw/migrations/versions/` (нумерация `0001`, `0002`…).
`serve` применяет их при старте (отключается `--no-migrate`); приложение отказывается работать,
если версия схемы не совпадает с ожидаемой. База от версии 0.1 (без таблицы `alembic_version`)
распознаётся и помечается как `0001`.
